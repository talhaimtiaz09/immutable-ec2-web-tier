Immutable EC2 Web Tier with Zero-Downtime Rollouts

Talha Imtiaz, DevOps Engineer

A small API on an EC2 fleet where servers are never patched in place. Every change becomes a new golden AMI, the Auto Scaling group replaces the fleet behind a load balancer, and a CloudWatch alarm rolls a bad release back on its own. All of it is Terraform, applied from CI with no static AWS credentials.

Topology

Architecture

Three subnet tiers across two Availability Zones. Each tier accepts connections only from the security group of the tier above it.

  • InboundOnly the ALB is reachable from the internet. The app security group accepts connections from the ALB security group and nothing else.
  • ComputeAn Auto Scaling group of 2 to 4 t4g.small instances in private subnets, with health_check_type = "ELB" and target tracking on ALBRequestCountPerTarget.
  • DataPrivate Postgres, publicly_accessible = false, port 5432 open only to the app security group. RDS manages the master secret in Secrets Manager, so no password sits in state or tfvars.
  • EgressOne fck-nat instance and an S3 gateway endpoint. Packages are baked into the AMI at build time, so the fleet barely needs the internet.
  • Accessaws ssm start-session, authenticated by IAM and logged. No security group opens port 22.
  • SignalsThe CloudWatch agent ships app logs plus memory and disk metrics, with its config pulled from Parameter Store at boot. Alarms on target 5xx, unhealthy hosts, p95 latency and RDS CPU and storage go to SNS email.
Delivery

Release flow

A release is a commit that changes one AMI ID. Everything after the approved merge is automatic, including the rollback.

  1. developer

    Commit to app/ or packer/

    The change triggers ami.yml.

  2. GitHub Actions · OIDC → ami-builder role

    Packer and Ansible bake a golden AMI

    Amazon Linux 2023 on arm64. Packer connects through SSM Session Manager (ssh_interface = "session_manager"), so even the build opens no port 22. The AMI is tagged with the git SHA, app version and build date.

  3. GitHub Actions

    A pull request bumps ami_id

    One line in envs/lab/lab.tfvars. The release is now a reviewable diff.

  4. terraform.yml · OIDC → read-only plan role

    Checks and plan on the pull request

    fmt -check, validate, tflint, trivy config, then terraform plan. The plan is posted as a PR comment. The plan role cannot change anything.

  5. reviewer · GitHub Environment

    Approved apply from main

    A required reviewer gates the job. The apply role trusts only jobs in this repository's lab GitHub Environment, matched on the OIDC sub claim.

  6. scripts/rollout.sh · AWS Auto Scaling

    Instance refresh replaces the fleet

    Terraform only creates the new launch template version. The rollout script then starts a rolling refresh with that version as the desired configuration, minimum healthy at 100% and maximum at 200%. New instances pass /healthz before old ones are removed, and the ALB's deregistration delay matches the app's graceful shutdown on SIGTERM.

Healthy

Refresh completes

Old instances drain and terminate. /version reports the new SHA and AMI ID.

Alarm fires

Auto-rollback

Target 5xx or UnHealthyHostCount breaches during the refresh. Auto Scaling returns to the previous launch template without a human, and the CI job fails so the bump gets reverted.

Rollback is git revert

The AMI ID lives in a committed tfvars file, not a data-source lookup. Reverting the bump commit sends the previous image back through the same plan, approval and refresh.

# envs/lab/lab.tfvars, after git revert
- ami_id = "ami-<new build>"
+ ami_id = "ami-<previous build>"

What minimum healthy 100% means

Capacity never drops below the desired count during a release. Maximum healthy at 200% gives the refresh room to launch first. The price is briefly running extra instances.

Trade-offs

Design decisions

Each choice, why it was made, and what it costs.

Immutable images instead of patching in place

Why
No configuration drift between instances. Rollback is a previous AMI, not an undo script, and what was tested is exactly what runs.
Trade-off
Every change, even a one-line config edit, costs an image build and a fleet refresh.

A shallow ALB health check

Why
If /healthz checked the database, one DB blip would mark every instance unhealthy and the ASG would terminate a healthy fleet. The deep check lives in /readyz and in alarms, not in replacement decisions.
Trade-off
An instance that cannot reach the database stays in service. Alarms catch it instead of the health check.

Minimum healthy at 100% during refresh

Why
New capacity launches before old capacity is removed, so a release never shrinks the fleet below its desired size.
Trade-off
Extra instances run briefly, and the refresh takes longer than a terminate-first rollout.

SSM Session Manager instead of a bastion

Why
Nothing listens on the network. Access is authenticated by IAM and logged, and there are no SSH keys to rotate.
Trade-off
Access depends on the SSM agent and an egress path. If fck-nat is down, so is the shell.

The AMI ID in a tfvars commit

Why
A data-source lookup of the latest AMI would change the fleet without a diff. A committed ID makes every fleet change a reviewed diff, and rollback is git revert.
Trade-off
One extra pull request per image build, opened by CI.

The rollout runs outside Terraform

Why
AWS rolls a failed refresh back to the configuration saved on the group before the refresh started. Terraform's instance_refresh saves the new version first, so its rollback would redeploy the bad AMI. Terraform ignores the group's launch template, and a script starts the refresh with the new version as the desired configuration.
Trade-off
Terraform state no longer shows which version the fleet runs. The group itself, and the CI log, are the record.

Separate plan and apply roles over OIDC

Why
Code in a pull request can read but never change infrastructure. The apply role trusts only the reviewer-gated lab environment, and there are no AWS keys stored in GitHub.
Trade-off
Two IAM roles and their trust policies to keep in step as the stack grows.
Controls

Security posture

No inbound admin path, no long-lived credentials, and every secret scoped to one ARN.

No SSH, bastion or key pairNo security group opens port 22, the launch template sets no key pair, and the sshd service is disabled in the image. Operators and Packer builds both use SSM.
IMDSv2 requiredSet on the launch template, so instance credentials are only available through session-token requests.
Security-group chainALB → app → DB, each rule referencing the previous security group rather than a CIDR range. RDS is not publicly accessible.
Per-secret IAMThe instance profile has AmazonSSMManagedInstanceCore, CloudWatch publish, and secretsmanager:GetSecretValue on the one DB secret ARN only.
No static CI keysGitHub Actions assumes roles through OIDC. The plan role is read-only; the apply role trusts only the lab GitHub Environment, which requires a reviewer.
Encrypted state and dataState bucket with versioning, KMS encryption, public access blocked and native S3 locking. RDS encrypted with its own KMS key; gp3 root volumes encrypted.
Scanned before plantflint and trivy config run on every pull request.

Spend

Cost decisions

Sized to cost about $2 a day while running, and nothing between sessions.

While runningApprox. per hour
ALB~$0.0225 + LCU
2 × EC2 t4g.small~$0.034
RDS db.t4g.micro~$0.016
fck-nat t4g.nano~$0.004
Total while up~$2 / day

Approximate on-demand figures used for planning, not a bill.

  • fck-nat instead of a managed NAT Gateway. A NAT Gateway costs roughly $32 a month idle. One t4g.nano covers a fleet that barely needs egress.
  • No interface endpoints. SSM interface endpoints in two AZs would add roughly $7 a month each per AZ. An S3 gateway endpoint is free and covers S3.
  • Destroy between sessions. terraform destroy on envs/lab at the end of each session; only bootstrap/ (state bucket, OIDC provider, CI roles) stays up.
  • Budget alert first. An AWS Budget alert at $10 a month exists before the first apply. Old AMIs are deregistered and their snapshots deleted, keeping the last three.
